# Viewer models

Four low-poly glTF 2.0 binaries the Cesium viewer (`../cesium.html`) draws in
place of point markers. All of them are **generic**: board-game-level shapes
built from boxes, prisms and lofts. None of them depicts a real aircraft,
vehicle or installation, and none carries insignia or markings.

| file | draws | nodes | size (m, L x W x H) | forward / up |
| ---- | ----- | ----- | ------------------- | ------------ |
| `fixed_wing.glb` | every blue aircraft | `airframe` | 14.0 x 10.0 x 3.9 | +Z / +Y |
| `ground_vehicle.glb` | mobile ground threats (`speed > 0`, not airborne) | `hull`, `turret` (child) | 8.0 x 3.2 x 5.2 | +Z / +Y |
| `sensor_site.glb` | stationary threats (`speed == 0`) | `site`, `sensor` (child) | 18.0 x 18.0 x 10.3 | +Z / +Y |
| `interceptor_drone.glb` | airborne threats (`airborne == True`) | `airframe` | 6.0 x 4.4 x 1.6 | +Z / +Y |

Which file draws which threat, the per-model scale, altitude offset, axis
correction, turret node and marker fallback all live in one typed registry,
`naigos/demo/models.py`, not in the page.

## Conventions

- Units are metres. Models are authored near real-world size and drawn with a
  `minimumPixelSize` so they stay legible from an AOI-wide camera; that
  enlargement is for legibility only. The **anchor point** -- the aircraft's
  simulated position, or the DEM height under a ground threat -- is what the
  simulation says; the model's extent around it is not a claim.
- glTF 2.0 axes: +Y up, +Z forward, +X left. CesiumJS's default glTF 2.0 axis
  correction maps this to its model frame (+X forward, +Z up), which is the frame
  `Cesium.HeadingPitchRoll` rotates, so every registry axis offset is zero.
- The `turret` and `sensor` nodes rotate about their local +Y. The viewer turns
  them toward an aircraft only while the simulation's track matrix says this
  threat holds a track on it (see `naigos/demo/attitude.py`); otherwise they
  face the platform's simulated heading.

## If a model fails to load

The viewer checks each file's glTF header before building entities. A missing
or malformed file falls back to a point marker for that class only, and the HUD
shows a one-time warning naming the file. The normal path never uses the
fallback; `python -m naigos.demo.live --smoke-render` reports the fallback count
without opening a browser.
